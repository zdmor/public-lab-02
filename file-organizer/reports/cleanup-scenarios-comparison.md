## 4. 方案 3：重装 Windows + 重整 D:

### 4.1 定义

完整备份 → 干净安装 C: → 恢复最小应用/数据 → 重整 D: → 验证 → 退役旧卷/旧备份。

- C: 干净装机模型 **60–80 GiB（ESTIMATE ±20）**，但它只是 OS/驱动/更新/运行库，不含办公/IM/开发/量化/AI/用户数据；**不是 C: 的清理后总量**。
- C: 最小可用模型 **75–100 GiB（M1）**；D: **54–70（M1）/ 35–50（M2）**；合计 **129–170（M1）/ 110–150（M2）**。
- 目标容量是模型，不是实测释放；残余 45.9 在重装后预期被重置，但无法量化，不能写成"释放 45.9"。

### 4.2 目标容量与"差"

| 口径 | 今天 | 目标 M1 | 目标 M2 | 差（M1） | 差（M2） |
|---|---:|---:|---:|---:|---:|
| C: 已用 | 152.637 | 75–100 | 75–100 | 52.6–77.6 | 52.6–77.6 |
| D: 已用 | 117.091 | 54–70 | 35–50 | 47.1–63.1 | 67.1–82.1 |
| **合计已用** | **269.728** | **129–170** | **110–150** | **99.7–140.7** | **119.7–159.7** |
| 合计枚举 | 223.868 | 129–170 | 110–150 | 53.9–94.9 | 73.9–113.9 |

**必须区分**：
- 枚举差 54–95 GiB 与 INITIAL_STATE 的"枚举空间比最小模型多 54–95 GiB"一致，是可规划差。
- 已用差 99.7–140.7 GiB **包含 45.9 残余**，不是可删量；不能拿它做删除授权。
- 重装后 C: 目标 75–100，不是 60–80；60–80 只是 OS 层，应用/数据还要加回来。

### 4.3 方案 3 能解决、方案 1/2 不能解决的事

| 应用升级残留/注册表 | 不动 | 重建 |
| 驱动/更新历史 | 不动 | 重建 |
| 应用/许可证/凭据 | 保留 | **必须重建/重绑** |
| 用户数据 | 保留 | **必须备份/恢复** |

### 4.4 成本、风险与不可逆性

| 维度 | 评估 |
|---|---|
| 备份 | 必须完整备份 D: 已用 117.091 + C: 用户数据/配置/许可证；外部介质容量按实际备份清单计算，不预设 |
| 停机 | 1–3 天（ESTIMATE；取决于应用数量、许可证、驱动） |
| 应用重建 | 注册表 216 条卸载项（含组件，不等于 216 个应用）；需逐个重装/登录/授权 |
| 许可证/凭据 | 工程软件、办公套件、AI 客户端、开发工具可能绑定机器/账号；需重新激活；API key/证书需重新配置 |
| 数据风险 | 备份未验证、恢复遗漏、路径/权限变化、云同步冲突 |
| 驱动兼容 | 新系统可能缺少旧工程设备/加密狗/打印驱动 |
| 不可逆性 | 高：系统重置、应用设置、本地凭据、激活状态；只能靠完整镜像/备份回退 |
| 回退 | 全盘镜像或完整备份；没有则不可回退 |
| 建议 | 仅在运营方明确"像新机"目标、且备份/恢复演练通过后执行；不要为了省 30 GiB 直接重装 |

### 4.5 分阶段执行（不是一键）

1. **备份**：全量数据 + 应用清单 + 许可证/凭据清单；校验和。
2. **演练**：在外部介质/虚拟机验证恢复；确认关键应用可安装/激活。
3. **安装**：Windows 干净安装 + 驱动 + 更新。
4. **恢复**：最小应用集 + 数据；按 M1/M2 目标。
5. **验证**：启动、登录、许可证、数据完整性、云同步。
6. **退役**：旧系统/旧备份在验证通过后再处置；保留一个回滚窗口。
